Apa itu LKS Web Technologies?

LKS (Lomba Kompetensi Siswa) adalah lomba keahlian untuk siswa SMK. Di bidang Web Technologies, kamu tidak mengerjakan soal pilihan ganda. Kamu diminta membuat aplikasi web sungguhan di komputer panitia, dalam waktu terbatas. Setelah waktu habis, penguji membuka aplikasimu dan mencobanya satu per satu seperti pengguna biasa.

Dokumen yang kamu terima disebut kisi-kisi: bocoran garis besar soal. Isinya tema, fitur apa saja yang akan diminta, dan berapa nilai tiap fitur. Soal lengkapnya (naskah soal) baru dibagikan di hari lomba.

Kabar baiknya: karena kisi-kisi sudah menyebut fitur-fiturnya, kita bisa berlatih membuat aplikasi yang mirip sejak sekarang. Itulah isi web latihan ini.

1. Cara kerja web dan persiapan

Sekitar 30 menit. Gambaran besar dulu, supaya modul berikutnya terasa nyambung.

Client dan server

Bayangkan warung makan. Kamu (pembeli) memesan, pelayan mencatat lalu meneruskan ke dapur, dapur memasak, lalu makanan diantar kembali. Di web:

WarungWebContoh
PembeliClient, yaitu browserChrome di HP atau laptop
PesananRequest"Minta daftar event halaman 2"
DapurServerAplikasi Laravel + MySQL
MakananResponseData JSON atau halaman HTML

Bagian yang berjalan di browser disebut frontend (client-side). Bagian yang berjalan di server disebut backend (server-side). Modul 1 dan 2 lomba murni frontend. Modul 3 lomba berisi keduanya.

Tiga bahasa frontend

HHTMLKerangka dan isi: judul, tombol, form, gambar.
CCSSTampilan: warna, ukuran, susunan, versi HP.
JJavaScriptPerilaku: apa yang terjadi saat tombol diklik, ambil data, simpan data.

Request dan response HTTP

Setiap request punya method (jenis aksi) dan URL (alamat). Setiap response punya status code (kode hasil) dan body (isi).

GET https://jogjaevent.test/api/events?page=2&category=1

HTTP/1.1 200 OK
Content-Type: application/json

{ "data": [ { "id": 7, "title": "Ngayogjazz" } ], "meta": { "current_page": 2 } }
Bedah request di atas

GET : method untuk mengambil data. Method lain: POST (buat), PUT/PATCH (ubah), DELETE (hapus).

https://jogjaevent.test : alamat server.

/api/events : path, menunjuk data apa yang diminta.

?page=2&category=1 : query string, pilihan tambahan. Dipisah tanda &.

200 OK : status code, artinya berhasil.

Isi setelah baris kosong : body berbentuk JSON.

StatusArtinyaKapan muncul
200OKRequest berhasil
201CreatedData baru berhasil dibuat
401UnauthorizedBelum login atau token salah
404Not FoundData atau alamat tidak ada
422Unprocessable ContentIsian form tidak valid
500Server ErrorAda yang rusak di server

Lima kode pertama wajib dikuasai: kisi-kisi Modul 3 menyebutnya sebagai response minimum.

JSON

JSON adalah format teks untuk mengirim data. Bentuknya mirip objek JavaScript, tapi nama kuncinya wajib pakai tanda kutip dua.

{
  "id": 1,
  "title": "Pasar Kangen",
  "featured": true,
  "tags": ["kuliner", "antik"],
  "category": { "id": 3, "name": "Kuliner" }
}

Kurung kurawal { } untuk objek (punya nama), kurung siku [ ] untuk daftar (berurutan).

2. HTML dan CSS responsif

Sekitar 60 menit. Nilai "UI dan responsivitas" dan "Mobile UI/UX" ada di sini.

Kerangka HTML

HTML terdiri dari tag yang berpasangan: pembuka <p> dan penutup </p>. Tag bisa punya atribut, misalnya id dan class.

<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Jelajah Jogja</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header>
    <h1>Jelajah Jogja</h1>
  </header>
  <main>
    <section id="peta">...</section>
    <aside id="panel">...</aside>
  </main>
  <script src="script.js"></script>
</body>
</html>
Bedah kode baris per baris

<!DOCTYPE html> : wajib di baris pertama. Tanpa ini browser memakai mode lama yang aneh.

<meta name="viewport" ...> : wajib untuk tampilan HP. Tanpa ini, HP menampilkan halaman versi laptop yang dikecilkan.

<link rel="stylesheet" href="style.css"> : memanggil file CSS.

<header>, <main>, <section>, <aside> : tag bermakna (semantik). Lebih jelas daripada <div> di mana-mana, dan membantu aksesibilitas.

<script src="script.js"> di akhir body : JavaScript dimuat setelah semua elemen ada, jadi document.querySelector pasti menemukan elemennya.

Form yang benar

Form muncul di semua modul lomba: tambah marker, cari event, login, tambah data. Biasakan selalu memakai <label>.

<form id="form-lokasi">
  <label for="nama">Nama lokasi</label>
  <input id="nama" name="nama" required>

  <label for="kategori">Kategori</label>
  <select id="kategori" name="kategori">
    <option value="wisata">Wisata</option>
    <option value="kuliner">Kuliner</option>
  </select>

  <label for="deskripsi">Deskripsi</label>
  <textarea id="deskripsi" name="deskripsi"></textarea>

  <button type="submit">Simpan</button>
</form>

for="nama" pada label harus sama dengan id="nama" pada input. Hasilnya, label bisa diklik dan pembaca layar tahu input itu untuk apa. Ini termasuk nilai aksesibilitas di Modul 2 lomba.

CSS: memilih lalu mengatur

Aturan CSS = selector (siapa yang diatur) + deklarasi (diatur seperti apa).

body { font-family: system-ui, sans-serif; margin: 0; }   /* semua body */
.kartu { padding: 16px; border: 1px solid #ddd; }          /* class="kartu" */
#peta { height: 400px; }                                   /* id="peta" */
.kartu h3 { margin: 0; }                                   /* h3 di dalam .kartu */
button:hover { background: #2c3a8f; color: white; }       /* saat disorot mouse */

Ingat box model: setiap elemen adalah kotak berlapis. Dari dalam ke luar: isi, padding (jarak dalam), border (garis), margin (jarak luar). Tambahkan * { box-sizing: border-box; } di awal CSS supaya lebar kotak sudah termasuk padding dan border. Ini mencegah layout melebar sendiri.

Flexbox: menyusun sebaris

.toolbar {
  display: flex;
  gap: 8px;                 /* jarak antar isi */
  align-items: center;      /* rata tengah secara vertikal */
  justify-content: space-between;  /* dorong ke ujung kiri dan kanan */
  flex-wrap: wrap;          /* boleh turun baris kalau sempit */
}

Grid: menyusun kolom

.daftar {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 16px;
}

Baris ajaib di atas membuat kartu otomatis 1 kolom di HP, 2 kolom di tablet, dan 3 sampai 4 kolom di laptop, tanpa media query.

Mobile-first dan media query

Mobile-first artinya CSS ditulis untuk HP dulu, lalu ditambah untuk layar lebar. Modul 2 lomba menargetkan lebar sekitar 480 piksel.

/* HP dulu: panel di bawah peta */
main { display: flex; flex-direction: column; }

/* Layar 768px ke atas: panel di samping peta */
@media (min-width: 768px) {
  main { flex-direction: row; }
  #panel { width: 320px; }
}

/* Aplikasi mobile: batasi lebar supaya tetap rapi di laptop */
.app { max-width: 480px; margin: 0 auto; }

/* Gambar tidak pernah melebihi wadahnya */
img { max-width: 100%; height: auto; }
Tiga penyebab layout rusak di HP: lupa meta viewport, memakai lebar tetap seperti width: 900px, dan gambar tanpa max-width: 100%.

Latihan: halaman responsif

Kode di bawah langsung tampil hasilnya. Ubah, lalu tekan Jalankan. Centang Lebar HP untuk melihat versi HP.

Lihat kunci jawaban

  padding: 16px;
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 12px;
}
.kartu { margin-bottom: 0; }

@media (min-width: 600px) {
  header { display: flex; justify-content: space-between; align-items: center; }

3. JavaScript dasar

Sekitar 90 menit. Ini modul paling penting: dipakai di ketiga modul lomba.

Semua contoh di modul ini bisa dicoba di editor. Di laptop, kamu juga bisa mengetik langsung di tab Console DevTools.

  const ul = document.querySelector('#daftar');
  ul.innerHTML = '';                              // kosongkan dulu
  for (const l of lokasi) {
    const li = document.createElement('li');
    li.textContent = l.nama;                      // textContent aman

SVG dasar

SVG adalah gambar yang ditulis dengan tag, jadi bisa diubah dengan JavaScript seperti HTML biasa.

<svg id="peta" viewBox="0 0 600 450">
  <polygon points="40,120 160,90 190,150 ..." class="wilayah" />

  <text x="300" y="300">Bantul</text>

viewBox="0 0 600 450" artinya koordinat di dalam SVG selalu dari 0 sampai 600 (mendatar) dan 0 sampai 450 (menurun), berapa pun ukuran SVG di layar. Titik (0,0) ada di kiri atas. cx dan cy adalah titik tengah lingkaran.

Meminta data ke server butuh waktu. fetch mengirim request, lalu await menunggu jawabannya tanpa membekukan halaman. await hanya boleh dipakai di dalam fungsi yang diberi async.

const API = 'https://jogjaevent.test/api';

async function ambil(path) {
  const res = await fetch(API + path);       // 1. kirim request, tunggu response
  if (!res.ok) {                               // 2. status 4xx/5xx TIDAK otomatis error
    throw new Error('Gagal memuat (' + res.status + ')');
  }
  return res.json();                           // 3. ubah body JSON jadi object
}

async function coba() {
  try {
    const json = await ambil('/categories');
    console.log(json.data);
  } catch (err) {
    console.error(err.message);               // internet putus atau status error
  }
}

Bedah kode

res.ok : true kalau status 200 sampai 299. fetch hanya gagal kalau koneksi putus. Status 404 atau 500 tetap dianggap "berhasil", jadi wajib dicek sendiri.

throw new Error(...) : lempar error supaya ditangkap oleh catch.

res.json() : membaca body lalu JSON.parse. Hasilnya juga harus di-await, di sini sudah lewat return.

try { } catch (err) { } : jalankan isi try. Kalau ada error di mana pun di dalamnya, lompat ke catch.

Konsep database

Bayangkan lemari arsip. Database adalah lemarinya, tabel adalah satu map di dalamnya, baris adalah satu lembar data, dan kolom adalah isian di lembar itu (judul, alamat, dan seterusnya). Bahasa untuk memerintah database namanya SQL.

Membuat tabel

CREATE TABLE categories (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL
);

CREATE TABLE items (
  id INT AUTO_INCREMENT PRIMARY KEY,
  category_id INT NOT NULL,
  title VARCHAR(100) NOT NULL,
  description TEXT NOT NULL,
  address VARCHAR(150),
  FOREIGN KEY (category_id) REFERENCES categories(id)
);
Bedah kode

id INT AUTO_INCREMENT PRIMARY KEY : nomor unik tiap baris, naik sendiri 1, 2, 3.

VARCHAR(100) : teks pendek maksimal 100 huruf. TEXT : teks panjang.

NOT NULL : wajib diisi. address tidak punya NOT NULL, jadi boleh kosong.

FOREIGN KEY (category_id) REFERENCES categories(id) : category_id harus berisi id yang benar-benar ada di tabel categories. Inilah relasi: satu kategori punya banyak item.

JOIN, pencarian, dan pagination

Tiga fitur API di kisi-kisi (relasi, search, pagination) di dalamnya hanyalah SQL seperti ini. Nanti Laravel yang menuliskannya untukmu.

-- Gabungkan item dengan nama kategorinya
SELECT i.title, c.name AS kategori
FROM items i
JOIN categories c ON c.id = i.category_id;

-- Cari judul yang mengandung "pantai"
SELECT * FROM items WHERE title LIKE '%pantai%';

-- Pagination: 5 data per halaman, ambil halaman 2
SELECT * FROM items ORDER BY id LIMIT 5 OFFSET 5;

-- Hitung item per kategori
SELECT c.name, COUNT(i.id) AS jumlah
FROM categories c
LEFT JOIN items i ON i.category_id = c.id
GROUP BY c.id, c.name;

LIKE '%pantai%' : tanda persen artinya "teks apa saja". LIMIT 5 OFFSET 5 : ambil 5 baris, lewati 5 baris pertama. Rumusnya OFFSET = (halaman - 1) × per_halaman.

{
    public function authorize(): bool
    {

    {
        return [

Bedah aturan validasi

required : wajib diisi. nullable : boleh kosong.

integer, string : tipe data.

max:100 : untuk teks, maksimal 100 karakter.

exists:categories,id : nilainya harus ada di kolom id tabel categories.

authorize() harus return true. Kalau dibiarkan false, semua request ditolak 403.

        if ($request->filled('search')) {

        if ($request->filled('category_id')) {
            $query->where('category_id', $request->category_id);

    {
        return new ItemResource($item->load('category'));
    }

    // POST /api/items
    public function store(StoreItemRequest $request)
    {
        $item = Item::create($request->validated());
        return response()->json([
            'message' => 'Data berhasil dibuat',
            'data' => new ItemResource($item->load('category')),
        ], 201);
    }

    // PUT /api/items/5
    public function update(StoreItemRequest $request, Item $item)
    {
        $item->update($request->validated());
        return response()->json([
            'message' => 'Data berhasil diubah',
            'data' => new ItemResource($item->load('category')),

    }

    // DELETE /api/items/5
    public function destroy(Item $item)
    {
        $item->delete();
        return response()->json(['message' => 'Data berhasil dihapus']);
    }
}

Cara kerja token

Alurnya seperti gelang tiket festival. Kamu login sekali, server memberi token (gelang). Setiap request berikutnya, kamu menunjukkan gelang itu lewat header:

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use App\Models\User;

class AuthController extends Controller
{
    public function register(Request $request)
    {
        $data = $request->validate([
            'name' => 'required|string|max:100',
            'email' => 'required|email|unique:users,email',
            'password' => 'required|string|min:8',
        ]);
        $user = User::create($data);    // password otomatis di-hash
        return response()->json([
            'message' => 'Registrasi berhasil',
            'token' => $user->createToken('api')->plainTextToken,
            'user' => $user,
        ], 201);
    }

    public function login(Request $request)
    {
        $request->validate([
            'email' => 'required|email',
            'password' => 'required',
        ]);
        $user = User::where('email', $request->email)->first();
        if (! $user || ! Hash::check($request->password, $user->password)) {
            return response()->json(['message' => 'Email atau password salah'], 401);
        }
        return response()->json([
            'message' => 'Login berhasil',
            'token' => $user->createToken('api')->plainTextToken,
            'user' => $user,
        ]);
    }

    public function logout(Request $request)
    {
        $request->user()->currentAccessToken()->delete();
        return response()->json(['message' => 'Logout berhasil']);
    }
}
Bedah kode

$request->validate([...]) : cara singkat validasi tanpa Form Request. Gagal = 422 otomatis.

unique:users,email : email belum pernah dipakai di tabel users.

Hash::check(asli, hash) : password tidak pernah disimpan apa adanya. Yang disimpan versi acak (hash), lalu dicocokkan dengan fungsi ini.

createToken('api')->plainTextToken : buat token baru dan ambil teksnya untuk dikirim ke frontend.

currentAccessToken()->delete() : hapus token yang sedang dipakai. Setelah ini token lama dibalas 401.

Model User di Laravel versi baru punya cast 'password' => 'hashed', jadi password otomatis di-hash saat create().

Satu fungsi api() untuk semua request

Supaya tidak menulis header berulang-ulang (kualitas kode ikut dinilai), bungkus fetch dalam satu fungsi:

const API = 'http://127.0.0.1:8000/api';
let token = localStorage.getItem('token');

async function api(path, options = {}) {
  const headers = { Accept: 'application/json' };
  if (options.body) headers['Content-Type'] = 'application/json';
  if (token) headers.Authorization = 'Bearer ' + token;

  const res = await fetch(API + path, { ...options, headers });
  const json = await res.json().catch(() => ({}));   // body kosong pun aman

  if (res.status === 401 && token) keluar();          // token kedaluwarsa → kembali ke login
  if (!res.ok) {
    const err = new Error(json.message || 'Request gagal');
    err.status = res.status;
    err.errors = json.errors || {};                   // pesan validasi 422 per kolom
    throw err;
  }
  return json;
}

Lima teknik yang mudah ditiru

1. Aku, kita, kamu. Kamu contohkan dulu (aku), lalu kerjakan bersama (kita), lalu murid mengerjakan sendiri soal yang mirip (kamu). Jangan langsung loncat ke "kerjakan sendiri".

2. Tebak dulu sebelum menjalankan. Sebelum menekan Jalankan, tanya: "Menurut kalian hasilnya apa?" Tebakan yang salah membuat murid lebih ingat daripada penjelasan.

3. Sengaja buat error. Saat demo, hapus satu tanda kurung atau lupa e.preventDefault(), lalu tunjukkan cara membaca pesan error di Console. Murid jadi tidak takut melihat tulisan merah.

4. Jangan ambil alih keyboard. Saat membantu murid yang buntu, tunjuk dengan pertanyaan: "Error-nya di baris berapa?", "Variabel ini isinya apa? Coba console.log." Kalau kamu yang mengetik, murid tidak belajar apa-apa.

5. Berpasangan. Dua murid satu laptop: satu mengetik (driver), satu membaca soal dan mengecek (navigator). Tukar peran tiap 10–15 menit. Cocok untuk latihan proyek di Modul 5, 6, dan 11.

Lampiran: Git dan GitHub

Opsional. Di kisi-kisi 2027, Git hanya dipakai jika diperbolehkan panitia. Tetap berguna untuk menyimpan dan mengirim hasil latihanmu.

Apa itu Git?

Bayangkan main game yang bisa save. Git menyimpan kodemu sebagai save point yang namanya commit. Kalau kodemu rusak, kamu tinggal kembali ke save sebelumnya. GitHub adalah tempat menaruh save-an itu di internet, seperti Google Drive khusus untuk kode.

Alur kerja empat langkah

Edit file → git add (pilih file yang mau disimpan) → git commit (simpan dengan catatan) → git push (kirim ke GitHub).

Atur identitas (sekali saja)

git config --global user.name "Nama Kamu"
git config --global user.email "emailgithub@contoh.com"

Membuat repository pertama

mkdir latihan-lks
cd latihan-lks
git init
echo "<?php echo 'Halo, Jogja!';" > halo.php
git status
git add .
git commit -m "Tambah halo.php"
git log --oneline

git status adalah perintah paling berguna: ia memberi tahu apa yang berubah. Biasakan menjalankannya sebelum add dan commit.

Menyiapkan SSH key

SSH key itu seperti kartu akses. Dengan kartu ini GitHub tahu bahwa yang mengirim kode benar-benar kamu. Siapkan sekali saja di laptopmu.

ssh-keygen -t ed25519 -C "emailgithub@contoh.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub

Salin seluruh hasil perintah terakhir. Di GitHub buka Settings → SSH and GPG keys → New SSH key, lalu tempel. Uji dengan ssh -T git@github.com.

Mengirim ke GitHub

Buat repository kosong bernama latihan-lks di GitHub (tanpa README), lalu:

git remote add origin git@github.com:USERNAME/latihan-lks.git
git branch -M main
git push -u origin main

Setelah itu, setiap perubahan cukup: git add ., git commit -m "pesan", git push.

Aturan commit message: tulis apa yang berubah, misalnya "Tambah tabel items". Jangan "update" atau "asdf".

Latihan: langsung di terminal

Di bawah ini ada terminal tiruan. Ketik perintahnya di kolom paling bawah, lalu tekan Enter. Tidak perlu membuka laptop. Bingung? Tekan tombol Petunjuk.

Praktik di laptop sendiri

Kalau sudah lancar di terminal latihan, ulangi hal yang sama di Git Bash laptopmu.

Kalau ada error

Permission denied (publickey): SSH key belum ditambahkan ke GitHub, atau ssh-add belum dijalankan.

nothing to commit: kamu lupa menyimpan file di VS Code, atau lupa git add .

rejected / non-fast-forward: kamu membuat repo dengan README. Hapus repo lalu buat ulang tanpa README.
